## What is deliberately NOT in here

**`backend/.env`** — it holds `JWT_SECRET`, `PHONE_KEY` and `SETUP_SECRET`.
Secrets are never shipped in a code archive. Copy `backend/.env.example` to
`backend/.env` and fill it in, or keep the `.env` you already have.

If this is an existing deployment, **keep your existing `PHONE_KEY`**. It
cannot be rotated without re-encrypting every stored phone number. A different
key makes every number in the database unreadable.

**`backend/node_modules/`** — run `npm install` in `backend/`.

**`backend/package-lock.json`** — regenerated by `npm install`. If your team
pins dependencies, keep the lockfile from your own repository.

## Getting it running

```bash
cd backend
npm install
cp .env.example .env     # then fill in the four secrets
# apply database/ migrations in the order listed in README.md
npm run seed             # verifies the schema; seeds no accounts
npm start                # server on :4000, SMS worker as a child process
```

In a second terminal, if `SMS_PROVIDER=simulator`:

```bash
npm run simulator
```

Then open `http://localhost:4000/` and follow the six first-run steps in
`README.md`.

## Confirming it is healthy

```bash
node testing/run-all.js
```

Nine suites, no database and no running server needed. Expect
`All offline suites passed.`

## Two things to tell whoever receives this

1. **Rwanda phone numbers are 072, 073, 078 or 079 only.** The 077 prefix is no
   longer accepted anywhere — form, backend or SMS worker. Any existing 077
   number in the database will now fail at send time with a clear reason in
   `sms_reminder.last_error`. Those records need updating.
2. **Contacts are phone-only.** There is no email field anywhere in the system.
   If any existing `staff.contact` row holds an email address, that staff
   member will silently receive no SMS reminders until it is replaced with a
   mobile number.
